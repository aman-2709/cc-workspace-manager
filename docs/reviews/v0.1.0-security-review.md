# v0.1.0 pre-release security review (whole codebase)

Independent, adversarial review of the v0.1.0 release candidate (commit `5da25ca`, M4), not just the
last milestone. I did not write this code. Scope per the review brief: verify that every security
claim in `README.md` and `SECURITY.md` is backed by enforcement **and** a test that can fail, with
focus on the seccomp filter, Landlock + seccomp ordering, the TCP peer-UID check, the auth/token
lifecycle, Git hardening, the session parser and redaction, resume safety, privacy mode, the
install/uninstall scripts, the CI/release supply chain, and regressions of earlier findings.

**Method.** I read `REQUIREMENTS.md`, `ARCHITECTURE.md`, `SECURITY.md`, `README.md`, `CHANGELOG.md`,
the `docs/` set and the three prior reviews (`docs/reviews/m1`, `m2`, `m3`), then the full source
tree, the scripts, the systemd unit, and the CI and release workflows. Three areas were delegated to
isolated sub-reviews running against the same tree: HTTP/WebSocket/frontend/privacy, the
discovery/watch/tracker/db/paths slice, and a claim→test matrix; their results are folded in and
attributed. Where a finding is **demonstrated** it was run against the shipped library or the real
`target/debug` daemon in a synthetic environment under the session scratchpad; where it is **reasoned**
it was derived from the code only. Baseline: `CCWM_REQUIRE_LANDLOCK=1 CCWM_REQUIRE_INOTIFY=1 cargo
test` is green (208 unit tests plus every integration suite). `cargo fmt --check` and `cargo clippy`
were not re-run (no code was changed).

**Constraints honoured.** No repository file was modified. `~/.claude` / `$CLAUDE_CONFIG_DIR` was never
opened. Nothing was pushed, tagged or published. All experiments used synthetic environments or
throw-away repositories under the scratchpad; the maintainer's real `ccwm` daemon was not touched.

**Verdict.** No Critical findings on the primary tested platform (Linux x86_64, Landlock ABI 8). One
**High** finding (a whole class of malicious Git configurations still reaches arbitrary command
execution during routine inspection — Critical on the no-Landlock configurations the spec supports),
three **Medium**, and a set of **Low**/Info items. Most of the hard security work is sound and
test-backed: the TCP peer-UID check, the auth lifecycle, the Landlock ordering and self-verification,
the SQL layer, the session allowlist parser, privacy mode on the main payloads, and the supply-chain
pinning all hold up. The two most important weaknesses are a bypass of the Git filter-driver
neutralization and an overbroad claim about what the seccomp filter closes; both are backed by a
running demonstration below.

## High

### H1. A non-UTF-8 filter-driver name bypasses the filter neutralization, so `git status` runs an attacker-chosen program

**Where:** `src/git/parse.rs:123` (`filter_driver_names`, the lossy decode at `:128`), `src/git/parse.rs:171`
(`neutralizable`), `src/git/mod.rs:385` (enumerate), `:391` (the `neutralizable` gate), `:425`
(`status_args` builds the `-c filter.<name>.*=` overrides).

**What the spec promises.** This is the exact vector the whole §6 filter machinery exists to stop. §6
requires nulling "**every** driver in **every** scope", says "each alone leaves a verified bypass",
and states the flags "must hold on its own where Landlock is absent". `SECURITY.md` lists
`clean/smudge/process filters via .gitattributes, .git/info/attributes, global attributes` as
mitigated by "nulling every filter driver of every scope". §11.1 puts "malicious … Git configuration"
in scope. The M2 review's H1 (promisor lazy fetch) was the last hole of this class and was fixed.

**The hole.** `git status` re-hashes stat-dirty files and runs the `clean` filter a driver selects. ccwm
defuses this by enumerating drivers (`git config -z --get-regexp '^filter\..*\.(clean|smudge|process)$'`)
and passing `-c filter.<name>.clean=` (etc.) for each. But `filter_driver_names` decodes each key with
`String::from_utf8_lossy`, so a driver whose **name is not valid UTF-8** is turned into a name
containing U+FFFD (`EF BF BD`). `neutralizable` then accepts that mangled name, and `status_args`
emits `-c` overrides for the **wrong** name. The real driver — selected by `.git/info/attributes`
(`* filter=<realname>`), which `--attr-source=<empty tree>` does **not** neutralize — is never
disabled and runs. The code has no post-check that the override took effect, so nothing catches it;
the repository is reported `State::Ok`.

**Demonstrated** (shipped `git::Git::inspect`, no re-implementation, git 2.43.0; scratchpad `e1`, via a
throw-away crate linking the library by path). Three repos, each with `.git/config` defining a `clean`
filter that touches a sentinel and `.git/info/attributes` = `* filter=<name>`, the worktree made
stat-dirty:

| Driver name | `git config` enumerates it as | `Git::inspect` result | Sentinel? |
|---|---|---|---|
| `evil` (ASCII) | `filter.evil.clean` | `Ok` | **no** (correctly nulled) |
| `ev\xFFil` (invalid UTF-8) | `filter.ev␦il.clean` (lossy) | `Ok` | **yes — executed** |
| `caf\xE9` (Latin-1 `é`) | `filter.caf␦.clean` (lossy) | `Ok` | **yes — executed** |

Control: plain `git status` in the ASCII repo created the sentinel (the vector is live without the
mitigation). So the ASCII case proves the harness detects execution and that neutralization works for
valid names; the two non-UTF-8 cases prove the bypass.

**Preconditions and reach.** The attacker controls a repository that ccwm discovers and inspects: a
cloned/extracted malicious repo (extraction leaves files stat-dirty, so `status` re-hashes and the
clean filter fires), or a repo another user writes in a shared/group-writable discovery root. No user
interaction beyond ccwm's normal passive inspection. A non-UTF-8 config subsection name is legal in
Git and fully attacker-chosen.

**Impact.** Arbitrary program execution as the daemon's user, triggered by discovery alone. On the
primary tested platform (Landlock ABI 8 + the M4 seccomp filter) the helper is **contained** —
read-only outside ccwm's directories, no TCP connect, no new `socket()` — but it still executes, it
can read everything in the Landlock read set (the discovery roots **and the Claude session directory**),
and see M1 below for the datagram channel that is *not* contained. On a host **without full Landlock**
— which §11.5 explicitly supports ("runs anyway and reports") — the §6 flags are the only defense and
are bypassed: unconfined code execution as the user. This is the same class and (on degraded hosts)
severity the project rated **High** for the M2 promisor finding; I rate it High, **Critical where
Landlock is unavailable or below ABI 4**. The fundamental guarantee ("does not intentionally execute
their contents") and §6 are not met for this class of names.

**Fix.** Decide `neutralizability` on the raw bytes, not on a lossy string: in `filter_driver_names`,
when the driver-name slice of a key is not valid UTF-8 (or contains U+FFFD after a lossy decode, or any
byte `-c` cannot carry), treat it like the existing `=`-in-name case and **fail closed** — disable
worktree status for that repository (`State::StatusDisabledUnsafeConfig`). Equivalently, keep names as
`OsString`/bytes and pass the exact bytes in the `-c` override so it matches. Add test-4 cases with a
`0xFF` byte and a Latin-1 byte in the driver name, each with a plain-`git` control, asserting no
sentinel **and** `status_disabled_unsafe_config` (not `Ok`). Consider a defense-in-depth post-check:
after building the overrides, re-run the `--get-regexp` enumeration *with* the `-c` flags applied and
require every `filter.*.(clean|smudge|process)` effective value to be empty before trusting `status`.

## Medium

### M1. The seccomp filter does not close path-based Unix **datagram** sockets: `socketpair()` + `send_to()` reaches them

**Where:** `src/sandbox.rs:617-637` (`socket_filter`: the deny set is `SYS_socket` conditioned on the
family, `io_uring_*`, and their x32 entry points — `socketpair` is **not** filtered), `:653`
(`deny_new_sockets`); the claim: `SECURITY.md:69-76` ("the daemon and its Git and `claude` children
therefore cannot … connect to path-based Unix sockets (D-Bus, agents): the two gaps Landlock ABI ≤ 8
leaves"), `src/sandbox.rs:15-16`, `README.md` ("no new sockets once it is listening"), `CHANGELOG.md`
("This closes UDP and path-based Unix sockets, which Landlock leaves open"), and `compute_unconfined`
(`src/sandbox.rs:185-203`) which drops `unix_socket_connect_by_path` from `unconfined[]` once seccomp
is active.

**The hole.** The filter blocks `socket()`, so a process cannot create a *new* socket of an arbitrary
family. But `socketpair(2)` is a different syscall (`SYS_socketpair`) and is not in the deny set. An
`AF_UNIX`/`SOCK_DGRAM` socket obtained from `socketpair()` can be re-pointed on Linux: `send_to(path)`
and `connect(path)` to an external **path-based** datagram socket both succeed. So the datagram half of
"path-based Unix socket connect" is still open; only the stream half (D-Bus, SSH/GPG agents — all
`SOCK_STREAM`, which do need `socket()`) is actually closed.

**Demonstrated** (real Landlock ABI 8 + the shipped `deny_new_sockets()` applied in a throw-away
process; scratchpad). After the filter: `socket()` → `EPERM` (both `UnixDatagram::unbound` and a
`UnixStream::connect` fail with `EPERM`); `socketpair(AF_UNIX, SOCK_DGRAM)` → **ok**; `send_to()` to an
external path-based datagram listener → **ok (41 bytes)**; `connect()` to it → **ok**; `send()` after
connect → **ok (29 bytes)**. The external listener received both datagrams.

**Impact.** A process confined by Landlock + seccomp (for example a Git child that reached execution via
H1, or — on any host — the real `claude --version/--help` child) can send data to any local path-based
**datagram** socket, e.g. the syslog socket `/dev/log` or systemd-journald's datagram socket. Where
syslog forwards off-host (common in managed fleets) that is an exfiltration channel for data the
process can read — and the Claude session directory is in the Landlock read set. It does not reach
D-Bus/agents (stream). The practical severity is Medium: it needs either H1 or a hostile `claude`/`git`
binary, and an off-host-forwarding datagram sink to exfiltrate; but independently of exploitability the
three user-facing documents and the `unconfined[]` report **overstate** the confinement, which the spec
forbids ("Never claim a protection that isn't active").

**Fix.** Either add `SYS_socketpair` to the deny set (verify first that the daemon and its `git`/`claude`
children need no socketpair after the listeners are bound — Tokio's signal/IO paths use `eventfd`/pipes,
not socketpair, so the risk is low but must be checked and tested), **or** correct the wording in
`SECURITY.md`, `README.md` and `CHANGELOG.md` to "blocks creating new sockets via `socket()`; a
`socketpair`-derived `AF_UNIX` datagram socket can still reach path-based datagram sockets" and keep
`unix_socket_connect_by_path` (datagram) in `unconfined[]` even when seccomp is active. Add a
`tests/sandbox.rs` case: under the filter, `socketpair(SOCK_DGRAM)` + `send_to` to an external path
must fail (if the syscall is denied) or the claim text must match (if it is not).

### M2. A hostile repository drives the daemon to unbounded memory via many large `.gitignore` files

**Where:** `src/watch/tree.rs:22` (`MAX_GITIGNORE_BYTES` = 1 MiB **per file**), `:210-216` (one compiled
layer added per directory that has a `.gitignore`), `:60-80` (layers retained), `:21` (the only other
bound is 100 000 entries); the layers live in `ProjectState.ignore` (`src/watch/mod.rs:299`).

**The hole.** Each `.gitignore` is capped at 1 MiB, but nothing caps the **total** across a project, and
the tree walk is bounded by entry count, not by ignore-rule memory. A repository with a `CLAUDE.md`, a
`.git`, and many directories each containing a (hard-linked, so tiny on disk) 1 MiB `.gitignore`
compiles and retains one matcher per directory.

**Demonstrated** (release build, synthetic env): 10 such files (≈11 MB on disk) drove RSS from a ~26 MB
baseline to **860 MB**, retained after "reconciliation finished"; a debug run with 100 files reached
**6.9 GB** and was still climbing. The tree walk has no cancel flag, so SIGTERM did not interrupt it
promptly (a debug run was still alive 3 s after logging "shutting down").

**Impact.** Availability. §11.1 puts malicious project content in scope; cloning such a repo next to an
existing project registers it live or at the next scan with no interaction. With `Restart=on-failure`
and no `MemoryMax=` in the unit, an OOM kill loops while the repo exists. (The 50 MB RSS performance
*target* of §15 is also blown.)

**Fix.** Cap total `.gitignore` bytes and patterns per project (e.g. 1 MiB / 20 000 patterns), lower the
per-file cap, mark the project `partial` when exceeded, and give the tree walk the shutdown cancel flag.

### M3. The "port impostor" residual is understated: origin-scoped browser state outlives the impostor and runs under the real daemon

**Where:** `SECURITY.md` "Residual risks → Impostor UI" and §11.3; `web/index.html:7-8` (fixed,
unversioned `/app.css`, `/app.js`); `src/http/middleware.rs:54-57` (assets get `Cache-Control:
no-cache`, nothing stronger); `web/app.js` (no service-worker registration or check; the reconnect loop
at `:946-956` sends the session token to whatever holds the port within ≤30 s).

**The gap (reasoned, standard browser behaviour; not demonstrated).** SECURITY.md says an impostor that
binds the port while ccwm is down "can read what the page stored (the session token) but cannot use it
(peer-UID check) … It can still show you false information." The peer-UID check constrains the
*impostor's own* connections. It does **not** constrain state the impostor wrote into the origin
`http://127.0.0.1:<port>` while it held the port: HTTP-cache entries (lifetime chosen by the serving
process), a service-worker registration, `localStorage`. That state is honoured again when the real
daemon returns, and any script it carries then runs in the user's own browser — whose connections pass
the peer-UID check, next to a valid session or the next sign-in link. So the real residual is the XSS
residual (read what the dashboard reads, call the state-changing API) reached **without any bug in
ccwm's page**, persisting until the origin's site data is cleared — not merely "false information". The
window opens whenever the port is free (before the user service starts, between stop/start, after a
crash, or permanently: a squatter binds first, the daemon exits 10, and exit 10 is in
`RestartPreventExitStatus`, so systemd does not retry).

**Fix (defense in depth; none complete alone).** (1) Keep the port from ever being free: a systemd
`ccwm.socket` unit (`ListenStream=127.0.0.1:<port>`) holding it across stop/restart/crash; document
that before login only lingering closes the window. (2) Detect: on `EADDRINUSE` and in `ccwm
doctor`/`status`, use the existing `sock_diag`/procfs lookup to find the listener's owner and warn
loudly when it is another UID, advising the user to clear the origin's site data before signing in. (3)
Send `Clear-Site-Data: "cache", "storage"` on a deliberate boundary (e.g. the `auth/exchange` response)
and unregister any service worker at `app.js` start. (4) Correct the SECURITY.md wording to name
"persistent script in the dashboard's origin" as the residual.

## Low

### L1. `sanitize_remote_url` leaves credentials in scp-like URLs and when a password contains `/`

**Where:** `src/git/parse.rs:212` (`sanitize_remote_url`). Claim: `SECURITY.md` "Remote URLs are stored
and shown without credentials (userinfo, query and fragment removed)".

**Demonstrated** (shipped function):

```
https://user:ghp_SECRETtoken@github.com/o/r.git   => https://github.com/o/r.git          (stripped ✓)
ssh://user:pw@host/x                               => ssh://host/x                        (stripped ✓)
user:s3cr3tpw@host.example:team/repo.git           => user:s3cr3tpw@host.example:team/…   (LEAKED)
https://user:pa/ss@host/x                          => https://user:pa/ss@host/x           (LEAKED)
```

The scp-like branch splits at the first `:`, so a `user:pass@host:path` URL is misread (`user` has no
`/`, so it is taken as the whole "host" head and nothing is stripped). A password containing `/` breaks
the authority/path split in the scheme branch. Both keep the credential. Severity Low: embedded
passwords in remote URLs are uncommon, and privacy mode hides remote URLs regardless — but the stored
value (DB, `/service/status`, logs if ever printed) contradicts the claim.

**Fix.** In the scp-like branch, strip userinfo before the first `/`-free `:` by splitting on `@` first;
in the scheme branch, cut the authority at the first `/`, `?` or `#` before searching for `@`. Add both
cases to `remote_urls_lose_credentials`.

### L2. A symlinked XDG ancestor makes ccwm watch (and attribute activity from) its own database

**Where:** `src/daemon.rs:272-275` (boundaries built from `dirs.hard_boundaries(&session_dir)`, only the
session dir canonicalized), consumed literally by `src/tracker/mod.rs:353-364` and
`src/watch/mod.rs:401-415`; only the marker scan canonicalizes (`src/discovery/walk.rs:41-52`).

**Demonstrated.** With `XDG_DATA_HOME` set to a symlink into a synthetic project (`alpha/store`), the
daemon started `fully_enforced`, held an inotify watch on `alpha/store/ccwm`, and reported alpha's
activity as `observed`, path `store/ccwm/ccwm.db-wal`, advancing every few seconds with no user action
as the WAL grew. Control: the same directory given literally was not watched. This breaks §5.1 ("never
generate activity from ccwm's own writes") and SECURITY.md's "ccwm's own directories are never walked":
the exclusion is by literal path, but the walk reaches the directory by its canonical path. A permanent
self-activity loop pins the project at "today". Needs a user-made symlinked XDG ancestor resolving
inside a project; no attacker. (Related, reasoned: `home` is the literal `$HOME` in several places, so a
symlinked home would defeat the "repo at home is not a project" guard and the `~/snap` exclusion.)

**Fix.** Canonicalize the four ccwm directories and `home` once in `daemon.rs` and pass the canonical
forms to all three consumers (tracker boundaries, watch boundaries, discovery). Add a process test with
a symlinked XDG parent inside a project.

### L3. Privacy mode leaves broad-read-rule paths in `sandbox.notes` of `/service/status`

**Where:** `src/service.rs:979-981` (privacy blanks only `sandbox.broad_read_rules`); `src/sandbox.rs:302-307`
(`flag_broad_reads` also writes the same paths into `notes`).

**Demonstrated.** With a discovery root that is an ancestor of the synthetic home,
`GET /api/v1/service/status?privacy=1` returned `broad_read_rules: []` but `notes: ["read rules
<path> are / or an ancestor of the home directory: …"]`. §10 lists "broad read rules in the service
status" (and roots) as hidden. Related (reasoned): a failed `PUT /settings` returns the absolute config
path in the 400 body even in privacy mode (`src/service.rs:771-776` → `src/config.rs:181-186`).

**Fix.** In privacy mode, replace the note with a path-free form (keep a count) or strip paths from
`notes` the way `broad_read_rules` is blanked; make the save-failure message path-free in privacy mode.
Add a `tests/sessions_api.rs` canary (the current status-privacy canaries are vacuous — see the test
section).

### L4. The ancestor/config trust check does not see POSIX ACLs

**Where:** `src/paths.rs:285-296` (`check_entry`: `let group_writable = mode & 0o020 != 0 && …`).

**Demonstrated.** After `setfacl -m u:nobody:rwx` on an ancestor (mode then shows `drwxrwx---`, group =
the user's private group), the daemon started and created its config directory beneath it; a plain 0770
directory with a non-private group was refused. So SECURITY.md's "refuses to start if any ancestor …
could be modified by another user" is false for ACL grants under the user-private-group convention (the
M1 L4 scenario, via ACL). The owner must have set the ACL, so it is Low. (Related, reasoned:
`private_group` checks only listed members, not another account whose *primary* gid equals the group.)

**Fix.** When an ACL mask grants group/other write (check for a `user::`/`mask::` extended ACL), refuse,
or document the limitation in SECURITY.md.

### L5. No request-body read timeout; a stalled body pins a connection slot (same-UID)

**Where:** `src/http/extract.rs:32` (`to_bytes(req.into_body(), MAX_BODY_BYTES).await`, no timeout);
only `header_read_timeout` is set (`src/http/mod.rs:257-261`).

**Demonstrated.** A request with a complete head but a body that never arrives (`Content-Length: 100`, 0
bytes) stayed open past 40 s for an authenticated `PUT /settings` and for unauthenticated
`POST /auth/exchange` with the allowed Origin; controls (silent socket, partial head, idle keep-alive)
all closed at 10.0 s. 64 such connections exhaust `MAX_CONNECTIONS` until restart (the Unix socket is
unaffected). Only a client that passes the peer-UID check can do it (same user), so this is a
robustness gap behind SECURITY.md's "10 s header-read timeout", not a cross-user issue; M1-review L5 is
fixed for heads, not bodies.

**Fix.** Wrap the body read in a timeout (408/400 on expiry) or add one request-timeout layer for the
non-WebSocket routes; add a socket test next to `incomplete_request_heads_time_out`.

### L6. `.gitignore` can be read from a `.git` above the discovery root (no-Landlock hosts)

**Where:** `src/watch/tree.rs:90-95` (ancestor search for a `.git`, stopping at `home`), `:274-301`.
**Reasoned.** With a root outside home (e.g. `/srv/code`), another user who creates `/srv/.git` +
`/srv/.gitignore` = `*` makes every project below lose activity and watches; Git itself would refuse
that repo (`safe.directory`), ccwm's matcher does not. Under Landlock the read is denied and skipped, so
this applies only without Landlock and with roots outside home. **Fix.** Stop the ancestor search at
the discovery root and require the `.git` to be owned by the user.

## Info / documentation accuracy

- **I1.** `SECURITY.md:~192` still says, of the `claude` CLI check, "UDP and path-based Unix sockets are
  not confined (see below)", which contradicts the M4 seccomp paragraph a few lines above. Reconcile
  with M1's conclusion (datagram path-based Unix sockets really are *not* fully confined; UDP is).
- **I2.** `README.md`/`CHANGELOG.md`/`SECURITY.md` "closes … path-based Unix sockets (D-Bus, agents)" —
  see M1; D-Bus/agents (stream) are closed, datagram paths are not.
- **I3.** WebSocket (`src/http/ws.rs:112-147`): a blocked `socket.send` suspends token revalidation, and
  the unbiased `select!` can forward one event after a revocation is signalled before the 4401 close.
  Reasoned; authenticated same-UID only. Use `biased;` with the revocation/tick arms first and a send
  timeout.
- **I4.** hyper's own 400 (malformed request line) carries no security headers (the router middleware
  never runs); empty body, no practical effect, but "strict CSP on every response" is exact only for
  router-produced responses.
- **I5.** `child_command` scrubs the IPC env list but does not `env_clear` for `claude` (unlike Git), so
  the `claude` children inherit the daemon's remaining environment. Intended (they need `PATH`/`HOME`),
  but worth a note.
- **I6.** `check_patch_values` (`src/service.rs:788-818`) refuses `/` and home-ancestors for
  `sessions.dir` but allows `sessions.dir == home` exactly, which would make the default root a hard
  boundary; `discovery.roots` has no analogous home-ancestor/`/` check in `PUT /settings` (validation
  only requires absolute paths). Low-risk (roots need a restart and the sandbox flags broad reads), but
  tighten for symmetry.
- **I7.** `PRAGMA wal_checkpoint(TRUNCATE)` results are ignored (`src/db/writer.rs:595,994`): a reader
  outlasting the busy timeout yields `busy=1`, not an error, so a failed truncate after a prompt-cache
  clear is silent. The data is still deleted (`secure_delete=ON`); only the WAL-truncation guarantee is
  best-effort. Check the row and retry/warn.
- **I8.** `claude/locate.rs:79-86` marks a `<encoded-dir>` "listed completely" even when the 100 000-file
  cap dropped entries, and `tracker/sessions.rs` then deletes the dropped sessions as gone. Only
  reachable far above the 819 files seen in practice.
- **I9.** `scripts/uninstall.sh --purge` disables and removes the unit **before** asking for the purge
  confirmation (`src/cli.rs` service_uninstall), so a declined purge still leaves the service
  uninstalled. The message ("nothing was deleted") refers to data only; consider saying so, or confirm
  before touching the unit.

## Security claims that are enforced **and** test-backed (spot-checked, sound)

- **TCP peer-UID check** (`src/http/peer.rs`): one exact `sock_diag` request for the client 4-tuple,
  `LISTEN`/`TIME_WAIT` excluded, IPv4-mapped canonicalized, ambiguity/`ENOENT`/error → reject; procfs
  fallback chosen by a startup self-test. Rich unit tests on hand-built replies (foreign tuple, own
  end, both states, wrong seq, `ENOENT`, `ENOMEM`, truncated, ambiguous) plus a real-loopback test that
  `sock_diag == procfs`. Decision function fails closed. Orphan sockets report uid 0 → rejected.
- **Landlock ordering & self-verification** (`src/sandbox.rs`, `src/daemon.rs`): applied single-threaded
  (`/proc/self/task` counted; ≠1 ⇒ `not_enforced`), worker + blocking-pool read probes, a write probe
  (`O_TMPFILE` in home) and a connect probe, each withdrawing exactly the claim it disproves; report
  claims only what was verified; `tests/sandbox.rs` (harness-less, real policy in a child) checks exact
  errnos for the process, a later thread, and grandchildren, with `CCWM_REQUIRE_LANDLOCK=1` turning
  "unavailable" into a failure.
- **Seccomp construction** (`src/sandbox.rs:597-648`): default `Allow`, `socket()` → `EPERM` unless
  `AF_NETLINK` + `NETLINK_SOCK_DIAG`, `io_uring_{setup,enter,register}` and the x32 entry points denied,
  foreign architecture ⇒ kill; TSYNC; inherited by threads created before/after and by children
  (demonstrated via `probe_socket → eperm`). (The socketpair gap is M1.)
- **Auth lifecycle** (`src/auth/*`): 32-byte CSPRNG tokens, SHA-256 at rest, `subtle` constant-time
  compare, single-use 30 s bootstrap with eviction, enforced 24 h rotation (overdue token usable only on
  `/auth/rotate`), 60 s rotation grace, sliding 30-day expiry, LRU cap of 10, hourly purge with socket
  revalidation. Tokens never logged (checked: no token in any `tracing` call in the read paths).
- **Git hardening** (`src/git/*`): empty env + the six §6 vars, no shell, `process_group(0)` with
  `killpg` on timeout and `WNOWAIT` to avoid pid reuse, bounded output, the full `BASE_ARGS`
  (per-protocol denies), `GIT_ALLOW_PROTOCOL=` + `GIT_NO_LAZY_FETCH=1`, `--attr-source=<empty tree>`,
  `--no-show-signature`, `=`-in-name fail-closed, promisor degrade. Test 4 covers each reachable vector

- **Session allowlist parser** (`src/claude/record.rs`, `parse.rs`, `prompt.rs`): only the §7.1 fields
  are declared; `toolUseResult`/`api-request-blob`/account ids etc. drained via `IgnoredAny` without
  materializing; content deserialized only after flags pass; incremental checkpoints never consume an
  unterminated line; rotation/shrink/rewrite reset; 8 MiB line cap; bounded 4 MiB prompt window opened
  `O_NOFOLLOW` and `fstat`-checked regular; redact-before-truncate; strict lower-case UUID stems; dedupe
  by id. DB canary scans (before and after clear, with a positive control) confirm nothing extra is
  stored.
- **Resume safety** (`src/claude/resume.rs`): strict UUID, POSIX single-quoting, and no command for a
  cwd with any C0/C1/DEL/bidi character; the pty paste test has control runs and a liveness paste per
  mode; continuations followed only within the same project.
- **SQL** (`src/db/*`): every statement parameterized; `format!` into SQL only splices constants; LIKE
  wildcards escaped; DB/WAL/SHM modes 0600; parser-version reindex in one transaction; prompt-cache
  guard checked inside the writer transaction; revocation commands await the queue (only `TouchSession`
  and `CachePrompt` may be dropped under back-pressure).
- **CLI ↔ daemon**: Unix socket in a 0700 dir, `SO_PEERCRED` both sides before any byte, stale socket
  removed only if it is a socket we own, instance `flock` taken before the DB opens, `ccwm open` takes
  the port from the daemon (impostor test: zero connections to a TCP listener). The CLI never speaks TCP.
- **Supply chain**: every GitHub Action is pinned to a full commit SHA — I verified each against upstream

## Test-coverage gaps (ranked)

The suite is strong where it counts (controls prove the harness can detect the bad outcome for tests
1, 3, 4, 8; exact errnos for Landlock/seccomp; DB canary scans with positive controls). The gaps that
matter for a release:

1. **CI requires a test that cannot pass (will go red on first push).** `ci.yml:122-125` sets
   `CCWM_REQUIRE_NETNS=1` when a probe `unshare --user --map-current-user --net true` succeeds, but
   test 5's network-namespace variant (`tests/process.rs`) wraps the daemon in a user namespace where
   `/` and `/tmp` show uid 65534, so `Owner::check_entry` refuses to start — the same effect
   ARCHITECTURE §13 records for systemd's user namespace. So SECURITY.md's "runs them in a network
   namespace where unprivileged user namespaces are allowed" has no test that has ever passed, and
   enabling it in CI likely fails the job. **Fix:** run the daemon's trust checks relative to the
   namespace mapping, or map the current user to a uid that owns the paths, or drop the netns variant
   and rely on strace (documenting that). Reasoned (userns is blocked on the dev host).
2. **seccomp `io_uring`/x32 denials are never exercised** — the only filter test is
   `assert!(!program.is_empty())` (`src/sandbox.rs:971`), so deleting the `io_uring`/x32 entries keeps
   every test green. And no real `git`/`claude` child is tested attempting a `socket()`. Add a
   grandchild that invokes `io_uring_setup` and an x32 `socket` and asserts `EPERM`. (This is also where
   an M1 regression test belongs.)
3. **test 5 (strace) traces only `connect,execve`**, so UDP `sendto`, a datagram `socketpair` send
   (M1), and seccomp-denied `socket()` are invisible. Trace `socket,sendto,sendmsg,io_uring_setup` too
   and require every post-listen `socket(` to be the netlink one or `EPERM`.
4. **`--purge` "refuses while a daemon holds the lock" has no test** (`src/cli.rs`), and the e2e purge
   uses an XDG-outside-home layout that would not detect collateral deletion of an XDG parent. Run the
   purge e2e with the `InsideHome` layout and decoys, and add a lock-held refusal test.
5. **Several privacy strips cannot fail**: `discovery.unreadable[].path`, `dev_roots[]`,
   `git.program`, `sandbox.broad_read_rules`/`notes` (L3), `settings.effective.config_path` — the
   fixtures contain no canary in those fields, and the status-endpoint canaries at
   `tests/sessions_api.rs:462-474` are vacuous in that environment. Seed canary roots/dev-roots/unreadable
   folders and a canary config-path; add a `for_client(false)` positive control for the WS variant.
6. **systemd directives are under-pinned**: five of the seven SECURITY.md names
   (`LockPersonality`, `RestrictRealtime`, `RestrictSUIDSGID`, `RestrictNamespaces`,
   `SystemCallArchitectures=native`) and `Environment=PATH` are not asserted in the unit test, which
   compares against `unit_text()` itself; `systemd-analyze verify` is skipped silently when absent. Pin
   the literals and emit a NOTICE (failure under `CI`) when the analyzer is missing.
7. **Silent skips with no CI gate**: the pty paste test (skips if python3/bash missing **or the driver
   errors for any reason**), the Landlock ABI<4/<6 assertions, the node UI tests, `systemd-analyze`.
   Add `assert!(env::var_os("CI").is_none())` before each skip and have the CI capability probe export
   the ABI so the matching assertions are required.
8. **Smaller**: no `same_file_system`-pruning test in either walk (deleting the device check fails
   nothing); the swap-race test never asserts a swap actually raced; the `XDG_RUNTIME_DIR` child-env
   scrub assertion is vacuous where the variable is unset; `sanitize_remote_url` has no scp-credential
   case (L1); redact-then-truncate passes in either order; the archive install path and
   `package-release.sh`/`sha256sum -c` have no automated test.
